## 🎮 포함된 프로젝트

### 1. [Zomvester](./Ludum_Dare_52)
- 싱글 Survivor 게임, 5인 팀 (클라이언트 개발)
- Ludum Dare 52 출품작
- **개발 기간:** 2023년 1월, 72시간 제한 개발
- **사용 엔진:** Unity
- **핵심 구현 요소:** 
  - 3일이라는 한정된 스코프 안에서 기획안을 구동 가능한 로직으로 빠르게 프로토타이핑
  - 실시간 디버깅 및 예외 상황(Interrupt)에 대한 즉각적인 트러블 슈팅 경험
  - UI 연출 및 인게임 액션 오브젝트 간의 기본적인 싱글턴 패턴 활용
  - 오브젝트 풀링 등의 기본적인 최적화 기법 학습

### 2. [Cosmos](./Turn_Based_Dungeon_Roguelite/) (가제)
- 턴제 로그라이트 게임, 1인 개발
- **개발 기간:** 휴학 기간 중 (2024년 말 ~ 2025년 초)
- **사용 엔진:** Godot
- **핵심 구현 요소:** 
  - 계층형 유한 상태 머신(HFSM) 기반의 매끄러운 턴제 전투 루프 제어
  - 다양한 버프/디버프 및 상태 효과를 유기적으로 처리하는 이벤트 큐(Event Queue) 시스템
  - CSV 파일을 활용한 대량의 아이템 및 스킬 정적 데이터 관리 구조 구축

### 3. 기타 장르 프로토타입 (디펜스 / 퍼즐 등)
- **사용 엔진 및 언어:** Unity / Godot
- **핵심 구현 요소:** 
  - 각 엔진의 특성에 맞는 2D/3D 정밀 충돌 처리 및 물리 연산 최적화
  - 가비지 컬렉션(GC) 부하 최소화를 위한 오브젝트 풀링(Object Pooling) 시스템 구현
  - 유저 편의성을 고려한 UI 흐름(Window/Popup) 제어 및 컴포넌트화

## 🛠️ 핵심 기술적 시도 및 문제 해결 경험

### 💡 구조적인 UI 상태 관리 및 예외 처리
- 여러 프로젝트를 단독 개발하며 UI 레이어 간의 결합도가 높아지는 스파게티 코드를 경계했습니다. 
- 데이터(상태)와 화면(뷰)을 분리하여, 데이터 단에서 요청을 원천 차단하고 UI는 데이터 상태를 구독(Subscribe)하여 스스로 비활성화되도록 유도하는 아키텍처를 연습했습니다.

### 💡 확장성 있는 게임 루프 및 데이터 관리
- 하드코딩을 지양하고 기획 데이터의 변경에 유연하게 대처할 수 있도록 데이터 구조화를 시도했습니다.
- 유니티의 ScriptableObject, 언리얼의 Data Table 구조를 학습하며 클라이언트 개발자로서 생산성을 높이는 툴링에 관심을 가졌습니다.
